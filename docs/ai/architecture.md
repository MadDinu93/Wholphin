# Architecture

Upstream Wholphin's structure is unchanged by the fork; this is the map of how it fits together. `W/` =
`app/src/main/java/com/github/damontecres/wholphin/`. Fork-specific parts are flagged *(fork)* and detailed in
[fork-customizations.md](fork-customizations.md).

## Gradle modules

| Module | Role |
|---|---|
| `:app` | The whole app. Flavors `default` / `appstore` / `firetv`, see [build-and-development.md](build-and-development.md) |
| `:wholphin-mpv-stub` | Compile-only stand-in for libmpv when the real AAR is missing; MPV throws at runtime |
| `:baselineprofile` *(fork)* | Generates the baseline/startup profile on a connected TV |

## Packages (`W/`)

| Package | Responsibility |
|---|---|
| `data/` | Room DB (`AppDatabase`, DAOs), `ServerRepository` (current server/user, sign-in, session restore), `data/model/` entities and app models (`BaseItem` wraps the SDK's `BaseItemDto`) |
| `preferences/` | `AppPreference` objects that describe settings UI over the proto `AppPreferences`; `UserProfileSettings` (per-user Room settings) |
| `services/` | Hilt singletons used by ViewModels: API calls, caches, navigation managers, player creation, workers |
| `services/hilt/` | `AppModule` (OkHttp clients, Jellyfin `ApiClient`, scopes), DB module |
| `ui/` | Compose screens + ViewModels, grouped by area (`main`, `detail/*`, `playback`, `nav`, `cards`, `preferences`, `setup`, `search`, `discover`, ...) |
| `util/` | Codec/device-profile logic (`util/profile/`), bitstream filters, pagers, dispatchers, logging |
| `api/seerr/` + generated | Seerr client generated by OpenAPI from `app/src/main/seerr/seerr-api.yml` at build time |

## Startup and lifecycle

1. `W/WholphinApplication.kt` — Hilt app, ACRA crash reporting, `HiltWorkerFactory` for WorkManager.
2. `W/MainActivity.kt` `onCreate` — restores the serialized `Destination` back stack (drops a trailing playback
   destination), wires window flags (secure for PIN users, keep-screen-on from `ScreensaverService`), calls
   `MainActivityViewModel.appStart(intent)`, then `setContent`.
3. `MainActivityViewModel.appStart`: *(fork)* starts `HomeRowsCache.preload` for the most recent server/user; then under
   a mutex runs `AppUpgradeHandler` → `IntentService` deep link handling → `handleAppStart` (auto sign-in via
   `ServerRepository.restoreLastSession()` or server list).
4. `W/MainContent.kt` — outer `NavDisplay` over `SetupDestination` (`Loading`, `ServerList`, `UserList`, `AppContent`),
   driven by `SetupNavigationManager`. `AppContent` renders `ApplicationContent`.
5. `W/ui/nav/ApplicationContent.kt` — inner `NavDisplay` over `Destination` (`NavigationManager.backStack`), backdrop,
   *(fork)* hero trailer layer. See [ui-and-navigation.md](ui-and-navigation.md).

`onResume` refreshes the user DTO; `PlaybackLifecycleObserver` pauses/stops playback with the activity lifecycle.
On user change, `UserSwitchListener` sets locale and loads home settings (server-plugin check runs in parallel *(fork)*).

## Jellyfin communication and auth

- `services/hilt/AppModule.kt` builds one SDK `Jellyfin` instance and a singleton `ApiClient`
  (`jellyfin.createApi()`); `ServerRepository` sets its base URL and token when switching server/user.
- Two OkHttp clients, by qualifier:
  - `@StandardOkHttpClient` — no credentials. Use for any non-server URL (add-ons, trailers, Seerr).
  - `@AuthOkHttpClient` — adds the Jellyfin `Authorization` header (current user's token) to **every** request. Use
    only for URLs on the Jellyfin server (image loading, ExoPlayer streams).
- `ServerEventListener` subscribes to the server websocket (general commands/messages).
- Server plugin support (`ServerPluginApi`) can supply home settings; Seerr via `SeerrService`/`SeerrApi`.
- Remux quirks (subtitles only in PlaybackInfo, YouTube-wrapped trailer URLs) are handled in playback and trailer
  code, not in the API layer.

## Persistence

| Store | What | Where |
|---|---|---|
| Proto DataStore `AppPreferences` | App-wide settings | `app/src/main/proto/WholphinDataStore.proto`; defaults in `AppPreferencesSerializer`, upgrades in `AppUpgradeHandler` |
| Room (`AppDatabase`, v42, auto-migrations, schemas in `app/schemas/`) | Servers, users, per-user prefs (`JellyfinUserPreferences`), playback/track choices, pinned nav items, remembered tabs, Seerr | `W/data/` |
| Key-value DataStore | Per-user serialized JSON blobs | `KeyValueService` |
| Disk cache *(fork)* | Last home rows per server+user | `HomeRowsCache` → `cacheDir/home_rows/` |
| In-memory caches | Libraries (30 s, *fork*), trailers/themes per item (*fork*), suggestions, filter options | respective services |

How to add a setting: [DEVELOPMENT.md](../../DEVELOPMENT.md) ("How to add a new app setting").

## Background work

WorkManager workers: `SuggestionsWorker`, `LatestNextUpWorker`, `services/tvprovider/TvProviderWorker` (Android TV
"continue watching" row), scheduled by their `*SchedulerService`s from `MainActivity`. Coroutine scopes
`@IoCoroutineScope` / `@DefaultCoroutineScope` are app-lifetime `SupervisorJob` scopes; dispatchers via
`WholphinDispatchers`.

## Cross-component dependencies worth knowing

- `DeviceProfileService` (what the server may direct-play) and `PlayerFactory` (what the player does) must agree —
  e.g. DV7 conversion is checked in both via `DolbyVisionProfile7Conversion.isWanted`.
- `HeroTrailerService` is a singleton shared by home, card rows, details pages and `ApplicationContent`; its `owner`
  argument prevents pages from cancelling each other's trailers during navigation.
- `HomeRowsCache` serializes `HomeRowLoadingState`, which holds resource IDs — hence the version-code check.
- `NavDrawerService` feeds both the side drawer and the top bar.
